# Конструктор процессов и планов

Локальное веб-приложение для одного рабочего пространства. После первого запуска оно пустое: группы, процессы, проекты, дорожки, участники и элементы схемы создаются вручную. Рабочие данные сохраняются в IndexedDB браузера и не отправляются на сервер.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```powershell
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://127.0.0.1:5173`). Для проверки сборки: `npm run build`; для проверки правил дат: `npm test`. Данные связаны с адресом страницы и профилем браузера; для переноса используйте JSON-копию.

## Публикация на GitHub Pages

После изменений в main GitHub Actions собирает и публикует сайт по адресу https://valeratotsenko.github.io/map_builder/. Для первого запуска в настройках репозитория выберите Settings → Pages → Build and deployment → Source: GitHub Actions.

Данные хранятся в IndexedDB текущего браузера и адреса. Чтобы перенести их с локальной версии на опубликованную, скачайте JSON-копию через меню «Данные» и восстановите её на сайте.

## Работа

- **Карта процессов:** создайте группу и процесс, затем заполните текущее и целевое состояние. Этапы с датами и контрольные точки появятся на шкале. Участников и зависимости добавляйте через инспектор или панель действий.
- **План проектов:** создайте проект, поставку и хотя бы одну дорожку; затем добавляйте недельные блоки и при необходимости назначайте человека из общего справочника. Добавление и редактирование объектов выполняется в модальных окнах с кнопкой «Сохранить». Меню «Ещё → Объекты плана» открывает обзор проектов, поставок, людей, недельных задач, дорожек, блоков и событий. В карточке поставки можно указать объём задач в тестировании и разработке; распределение и выполнение рассчитываются по её недельным задачам. Поставки допускают точный, приблизительный или неизвестный срок.
- **Схема:** свободно разместите зоны и карточки действий, участников, проектов, направлений или заметок. Соединяйте карточки стрелками с короткими подписями. Зоны, карточки и связи в этом разделе являются самостоятельной визуализацией и не изменяют карту процессов или план проектов. Полотно сохраняет расположение и текущий обзор. На пустой схеме доступна кнопка «Создать пример» с тремя связанными шагами.
- **Мои задачи:** календарь показывает число дел и завершённых задач по дням. Нажмите на дату, чтобы открыть или свернуть доску «К выполнению / В работе / Сделано». Добавляйте задачи с датой и заметкой, редактируйте нажатием на название, меняйте статус в карточке или перетаскивайте карточку в другую колонку. Незавершённые задачи прошедших дней автоматически показываются сегодня; исходная дата сохраняется. Выполненные остаются в истории на дату завершения.
- **Связи:** поставку или блок можно вручную связать с этапом либо точкой процесса. Ссылка открывает объект в другом разделе, не меняя его сроки и статус.
- **Экспорт в Excel:** в плане выберите текущую выборку или весь план. XLSX содержит один лист с недельной загрузкой по проектам, поставкам и сотрудникам. Импорта Excel нет.
- **Резервная копия:** меню «Данные → Скачать JSON-копию» выгружает все данные, включая скрытые фильтрами. Для восстановления выберите JSON-файл, проверьте состав и подтвердите полную замену. Можно предварительно скачать копию текущего состояния. После успешного восстановления доступна команда возврата к предыдущему состоянию. Изменения автоматически сохраняются в IndexedDB. После изменений появляется кнопка «Скачать копию»; при закрытии или перезагрузке вкладки до скачивания копии браузер показывает стандартное предупреждение. Если закрытие отменить, JSON-копию можно скачать этой кнопкой. Браузеры не позволяют заменить стандартное предупреждение своим окном с кнопкой загрузки.

## Формат JSON-копии

Корневой объект содержит `format: "process-planner-workspace"`, `schemaVersion: 4`, время `exportedAt` в ISO 8601 UTC, объекты `workspace` и `data`. В `data` находятся прежние 16 коллекций, а также `canvas`, `canvasZones`, `canvasNodes`, `canvasEdges`, `weeklyAssignments` и `personalTasks`. Каждое недельное назначение содержит проект, необязательную поставку, человека либо `null`, понедельник недели, название, количество задач и заметку. Необязательное поле `completedCount` хранит число выполненных задач при заданном `count`; для записи без количества необязательное поле `completed` хранит отметку выполнения. Отсутствующие поля прогресса означают нулевое выполнение, при импорте копии версии 3 сохраняют эти значения и получают пустую коллекцию личных задач. У каждого объекта есть устойчивый `id`, `createdAt` и `updatedAt`. Сроки задаются `DateReference` со значением `kind: "unknown"`, `"exact"` или `"range"`; словесный ориентир находится в `text`. Границы недельных блоков хранятся как даты понедельников `YYYY-MM-DD`, последняя неделя включена. При импорте проверяются версия, типы, даты, уникальность ID и все внутренние ссылки. Копии версий 1 и 2 мигрируют с пустым списком недельных задач; версия 1 также получает пустую схему. Копии версий 1–3 получают пустой список личных задач. Неизвестные версии не открываются без миграции. Восстановление заменяет весь снимок атомарно и сохраняет локальную точку возврата.

У поставки необязательные поля `testingTaskCount` и `developmentTaskCount` хранят введённый вручную текущий объём задач. Старые копии версии 3 без этих полей сохраняют прежний смысл при переходе на версию 4. Показатели распределения и выполнения рассчитываются из недельных задач, у которых `deliveryId` равен ID поставки; записи без количества не прибавляются к числовым суммам.

## Ограничения MVP

Один пользователь и один браузерный профиль; нет облачной синхронизации, загрузки Excel/CSV, дневного или почасового масштаба, расчёта загрузки и автоматического переноса зависимых сроков. Вложения не хранятся; ссылки на внешние документы остаются текстом.
