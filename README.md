# Конструктор процессов и планов

Локальное веб-приложение для одного рабочего пространства. После первого запуска оно пустое: группы, процессы, проекты, дорожки, участники и элементы схемы создаются вручную. Рабочие данные сохраняются в IndexedDB браузера и не отправляются на сервер.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```powershell
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://127.0.0.1:5173`). Для проверки сборки: `npm run build`; для проверки правил дат: `npm test`. Данные связаны с адресом страницы и профилем браузера; для переноса используйте JSON-копию.

## Публикация на GitHub Pages

После изменений в main GitHub Actions собирает и публикует сайт по адресу https://valeratotsenko.github.io/map_builder/. Для первого запуска в настройках репозитория выберите Settings → Pages → Build and deployment → Source: GitHub Actions.

Данные хранятся в IndexedDB текущего браузера и адреса. Чтобы перенести их с локальной версии на опубликованную, скачайте JSON-копию через меню «Данные» и восстановите её на сайте.

## Работа

- **Карта процессов:** создайте группу и процесс, затем заполните текущее и целевое состояние. Этапы с датами и контрольные точки появятся на шкале. Участников и зависимости добавляйте через инспектор или панель действий.
- **План проектов:** создайте проект, поставку и хотя бы одну дорожку; затем добавляйте недельные блоки и при необходимости назначайте человека из общего справочника. Новый объект появляется в плане после нажатия «Сохранить»; существующие объекты сохраняются при изменении полей. Поставки допускают точный, приблизительный или неизвестный срок.
- **Схема:** свободно разместите зоны и карточки действий, участников, проектов, направлений или заметок. Соединяйте карточки стрелками с короткими подписями. Зоны, карточки и связи в этом разделе являются самостоятельной визуализацией и не изменяют карту процессов или план проектов. Полотно сохраняет расположение и текущий обзор. На пустой схеме доступна кнопка «Создать пример» с тремя связанными шагами.
- **Связи:** поставку или блок можно вручную связать с этапом либо точкой процесса. Ссылка открывает объект в другом разделе, не меняя его сроки и статус.
- **Экспорт в Excel:** в плане выберите текущую выборку или весь план. XLSX содержит листы «Объекты плана» и «Недельный план». Импорта Excel нет.
- **Резервная копия:** меню «Данные → Скачать JSON-копию» выгружает все данные, включая скрытые фильтрами. Для восстановления выберите JSON-файл, проверьте состав и подтвердите полную замену. Можно предварительно скачать копию текущего состояния. После успешного восстановления доступна команда возврата к предыдущему состоянию.

## Формат JSON-копии

Корневой объект содержит `format: "process-planner-workspace"`, `schemaVersion: 2`, время `exportedAt` в ISO 8601 UTC, объекты `workspace` и `data`. В `data` находятся прежние 16 коллекций, а также `canvas`, `canvasZones`, `canvasNodes` и `canvasEdges`. У каждого объекта есть устойчивый `id`, `createdAt` и `updatedAt`. Сроки задаются `DateReference` со значением `kind: "unknown"`, `"exact"` или `"range"`; словесный ориентир находится в `text`. Границы недельных блоков хранятся как даты понедельников `YYYY-MM-DD`, последняя неделя включена. При импорте проверяются версия, типы, даты, уникальность ID и все внутренние ссылки. Копии версии 1 мигрируют с пустой схемой. Неизвестные версии не открываются без миграции. Восстановление заменяет весь снимок атомарно и сохраняет локальную точку возврата.

## Ограничения MVP

Один пользователь и один браузерный профиль; нет облачной синхронизации, загрузки Excel/CSV, дневного или почасового масштаба, расчёта загрузки и автоматического переноса зависимых сроков. Вложения не хранятся; ссылки на внешние документы остаются текстом.
