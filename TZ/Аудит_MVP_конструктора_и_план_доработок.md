# Аудит первой версии конструктора и план доработок

Проверено 12.10.2026 в браузере по адресу `http://127.0.0.1:5173/`. Оценка основана на пользовательских сценариях в работающем приложении и на структуре скачанных JSON/XLSX. Исходный код приложения в этой проверке не изучался.

## Краткий вывод

Основной сквозной сценарий работает: карта процессов и недельный план создают объекты, данные сохраняются после перезагрузки, участие отображается на карте, ссылка «поставка ↔ контрольная точка» ведёт в обе стороны. JSON-копия содержит объекты обоих разделов и восстанавливается с возможностью возврата. До наполнения реальными данными нужно исправить сохранение некорректного диапазона этапа и выгрузку Excel-фильтров.

## Подтверждённые дефекты

### P0 — этап сохраняет завершение раньше начала

**Как повторить:** открыть этап с началом 19.10.2026, поставить завершение 12.10.2026, нажать «Сохранить» и перезагрузить страницу. **Факт:** обе даты сохраняются; полоса этапа на шкале становится некорректной. **Ожидание:** сохранение блокируется с пояснением у поля завершения либо пользователь явно исправляет диапазон. Тестовому этапу возвращён корректный конец 30.10.2026.

**Исправление:** проверять порядок точных дат и границ приблизительных диапазонов на уровне общей модели и формы. Не записывать объект при ошибке. Проверить стадии, общие вехи и поставки тем же набором граничных случаев.

### P1 — фильтр XLSX охватывает только строку заголовков

**Как повторить:** скачать «Весь план» и открыть файл `plan-all-2026-10-12.xlsx`. На листах данные находятся в строке 4, а `auto_filter.ref` равен `A3:L3` и `A3:J3`. **Факт:** строки данных не входят в диапазон автофильтра. **Ожидание:** диапазон включает заголовок и все выгруженные строки (`A3:L4` и `A3:J4` для текущего набора).

**Исправление:** вычислять конец диапазона по фактическому числу строк отдельно для каждого листа, включая случаи пустого плана и поставок без блоков. Проверить сортировку и фильтрацию файла в Excel или совместимом редакторе.

### P1 — проверка самосвязи использует системный диалог браузера

**Как повторить:** «Карта процессов → + Связь», оставить один и тот же процесс источником и целью, нажать «Сохранить». **Факт:** браузер показывает JavaScript `alert` «Выберите разные связанные объекты». В ходе проверки этот диалог заблокировал управление исходной вкладкой средствами тестового браузера. **Ожидание:** понятная ошибка рядом с полем цели без блокировки страницы; недопустимый вариант лучше исключить из списка.

**Исправление:** убрать `alert` из валидации связей и использовать общий компонент ошибок формы. Поскольку исходная вкладка осталась с системным диалогом, для продолжения проверки открыта новая рабочая вкладка.

## Доработки интерфейса

### P1 — единая и понятная модель создания и сохранения

На карте «+ Группа/Процесс/Этап» открывает пустую форму с кнопкой «Сохранить». В плане «+ Проект/Поставка/Блок» сразу записывает объект «Новый ...», а поля сохраняются автоматически. Закрытие инспектора оставляет заготовку в плане. Пользователь не может предсказать момент записи и легко накопит пустые объекты.

**Предложение:** выбрать один принцип для обоих экранов. Предпочтительно создавать объект после первого явного сохранения; автосохранение оставить для редактирования существующего объекта с индикатором «Сохранено». Если автосоздание необходимо для быстрого клика по неделе, показать «Отменить создание» до заполнения. **Приёмка:** открытие и закрытие незаполненной карточки не увеличивает число объектов.

### P2 — больше полезного места на карте при открытом инспекторе

В окне около 1100 px левое дерево и правый инспектор оставляют узкую область для временной шкалы; при масштабе «Месяцы» двухнедельный этап превращается в короткую полосу с обрезанной подписью. Добавить режим временного скрытия дерева, регулируемую ширину инспектора и автоматический переход к более крупному масштабу для выбранного короткого этапа. Полная подпись и даты должны быть доступны без горизонтальной прокрутки.

### P2 — локализация и ясность экрана восстановления

Экран проверки JSON показывает технические ключи `groups`, `processes`, `actors`, `projects`, `deliveries`, `weekBlocks`. Заменить их на «Группы», «Процессы», «Участники», «Проекты», «Поставки», «Недельные блоки». Ошибку несовместимой версии показывать без служебного префикса `Error:`. Добавить краткое объяснение, что копия заменит данные обоих разделов.

### P2 — поведение недельных дат и мелкий текст

Если поставить конец блока раньше начала, приложение молча передвигает начало назад. Округление любого дня до понедельника тоже происходит без пояснения в момент ввода. Показать короткое уведомление о нормализации и не менять второе поле неожиданно. Исправить подпись «1 блоков» на «1 блок».

## Очерёдность выполнения

1. **До внесения реальных планов:** исправить проверку дат этапов; добавить проверки диапазонов для остальных дат; исправить диапазон автофильтра XLSX. Для каждого случая сделать автоматический тест модели/экспорта и один ручной сценарий в интерфейсе.
2. **Следующий проход по основному UX:** убрать системные `alert`, унифицировать создание и сохранение, добавить явную обратную связь об автосохранении. Повторить сценарий «создать и закрыть пустую карточку» в обоих разделах.
3. **Перед плотным использованием:** доработать компоновку карты с инспектором, подсказки коротких полос, тексты восстановления и поведение недельных дат. Проверить на ширине ноутбука и на насыщенной карте с несколькими группами и связями.
4. **Отдельный регрессионный проход:** JSON round-trip в чистом профиле, отклонение повреждённых ссылок, ошибка записи и атомарность восстановления; XLSX для пустого и отфильтрованного плана; удаление связанных объектов; зависимости между разными этапами и передачи участников. Эти сценарии в текущем ручном проходе не были полностью проверены.

## Критерий готовности следующей версии

Некорректный срок нельзя сохранить; XLSX фильтрует реальные строки; создание пустой карточки не загрязняет план; сообщения об ошибке не блокируют браузер; карта остаётся читаемой с открытым инспектором. После этого можно переносить в конструктор рабочие процессы и проектный план.
