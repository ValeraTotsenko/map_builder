# ТЗ-дополнение: задачи по людям и неделям в «Плане проектов»

Дата: 13.10.2026. Это доработка существующего экрана «План проектов», без отдельного модуля и без почасового планирования.

## Задача

Сейчас проект и поставка могут иметь сроки, а рабочий блок — человека и интервал из нескольких недель. По такой полосе нельзя понять, **какие именно задачи назначены человеку на конкретную неделю**. Добавить слой недельных назначений: проект и релиз задают контекст, а содержимое недельных колонок можно заполнять и редактировать.

Пример ожидаемого результата: при выборе недели **19–25.10.2026** видно, что у Кирилла запланировано **5 задач по Pilot** и **10 по Rental Booster**, всего **15 задач**. Из итоговой цифры можно открыть сами записи.

## Что добавить на экран

1. **Редактируемые ячейки недель.** В пересечении строки проекта/поставки и недели по клику открывается компактное окно со списком назначений этой недели и кнопкой «Добавить задачу». Проект, поставка и неделя подставляются из выбранной ячейки. Назначение можно изменить, перенести на другую неделю, скопировать на следующую неделю или удалить. Пустая ячейка показывает ненавязчивый `+` при наведении/выделении.
2. **Запись недельного назначения.** Обязательные поля: короткое название, проект и неделя. Ответственный выбирается из существующего списка «Люди» либо остаётся «Не назначено». Поставка необязательна. Для быстрого чернового планирования разрешить одну запись на *пакет однотипных задач* с полем «Количество задач» (целое число от 1, по умолчанию 1). При количестве больше 1 показывать `×5`, чтобы запись не выглядела как одна задача. Заметка необязательна. Запись без человека попадает в отдельный итог.
3. **Обозначение в ячейке.** Показывать имя человека и число задач, например `Кирилл · 5`, а при раскрытии — названия записей. Использовать цвет человека из его карточки и одновременно текстовое имя; цвет не должен быть единственным способом различить назначения. Название проекта видно в строке и в раскрытой записи. При избытке записей показывать первые несколько и `+ ещё N`, сохраняя доступ ко всему списку.
4. **Выбор недели и итоги.** Клик по заголовку недели выделяет колонку и открывает компактный итог внизу плана: строки — люди, внутри — проекты с количеством задач; справа итог человека, внизу итог проекта и общий итог недели. Показать также «Не назначено». Клик по числу раскрывает записи, из которых оно сложилось. Итоги пересчитываются сразу после любого изменения и явно помечены как итог **по текущим фильтрам**.
5. **Быстрый ввод.** Помимо создания по одной записи, в окне недели дать вставить несколько названий строками: одна строка = одна задача с количеством 1 и выбранным человеком. Это нужно для переноса короткого недельного списка без заполнения полной формы для каждой строки.

## Правила данных и подсчёта

- Недельное назначение хранит `weekStart` (понедельник), `projectId`, необязательный `deliveryId`, `personId` или `null`, название, количество и заметку. Каждая запись относится ровно к **одной неделе и одному ответственному**. Если работа продолжается на следующей неделе, создаётся отдельное назначение на неё. Один блок на несколько недель не прибавляется автоматически в каждую недельную сумму.
- В итогах суммируется поле «Количество задач»; это **число запланированных задач, не часы, трудоёмкость или процент занятости**. Полосы сроков поставок и существующие рабочие блоки сохраняются. Их не считать задачами второй раз. По возможности использовать или расширить текущую модель `weekBlocks`; если для однозначного недельного учёта нужна отдельная сущность, связать её с проектом, поставкой и человеком без дублирования справочников.
- Цвет закреплён за человеком, а не за конкретной задачей. При смене цвета человека обновляются все его метки. Если неделя назначения находится вне показанного срока поставки, показать предупреждение, но разрешить сохранение: подготовка может начинаться до срока релиза.
- Для новых назначений использовать уже существующий список людей плана. Не создавать второй справочник исполнителей и не требовать назначения роли из карты процессов.

## Сохранение и экспорт

Новые записи автоматически сохраняются вместе с остальным рабочим пространством. Включить их в общий JSON-экспорт и восстановление; старые копии должны открываться с пустым списком недельных назначений. Экспорт плана в Excel дополнить простым листом/таблицей: неделя, человек, проект, поставка, задача или пакет, количество; затем итоги по человеку и проекту. Импорт Excel в эту доработку не входит.

## Приёмка

1. В строке поставки Pilot пользователь выбирает неделю 19–25.10.2026, создаёт для Кирилла пакет «Проверки Pilot» с количеством 5. В строке Rental Booster на той же неделе создаёт пакет из 10 задач. В недельном итоге у Кирилла показаны Pilot — 5, Rental Booster — 10, всего — 15.
2. По клику на `5` и `10` открываются исходные записи; смена ответственного или количества сразу меняет метки ячеек и итоги. Цвет и текст исполнителя присутствуют одновременно.
3. Задачи на соседней неделе не попадают в итог выбранной. Существующий рабочий блок на диапазон недель не увеличивает итог задач.
4. После перезагрузки назначения остаются. Общая JSON-копия восстанавливает их; старая копия без них открывается без ошибки. Excel-экспорт содержит строки назначений и правильные итоги.

Результат: в текущем плане можно отвечать на два разных вопроса — **когда готовится релиз** и **что конкретный человек делает в выбранную неделю** — без перехода к дням и часам.
